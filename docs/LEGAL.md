# محدودیت‌های حقوقی و فنی — و اینکه معماری چطور با آن‌ها سازگار شد

> این سند مشاوره حقوقی نیست. قوانین و شرایط سرویس تغییر می‌کنند؛ قبل از تصمیم‌های
> بزرگ با یک متخصص بررسی کن. هدف این سند این است که «چرا این‌طور ساخته شد» روشن باشد
> و ریسک‌های شناخته‌شده پنهان نمانند.

## ۱. GitHub Actions: کارخانه، نه موتور

متن شرایط GitHub برای محصولات تکمیلی (نسخه مؤثر ۲۷ اوت ۲۰۲۶) صریح است که Actions
نباید استفاده شود برای:

- استخراج رمزارز؛
- «ارائه‌ی یک اپلیکیشن یا سرویس مستقل/یکپارچه که خودِ Actions یا اجزای آن را برای
  اهداف تجاری عرضه کند»؛
- «هر فعالیتی که بار نامتناسبی روی سرورها بگذارد (مثلاً استفاده از Actions به‌عنوان
  CDN یا بخشی از یک اپلیکیشن serverless)»؛
- و در صورت استفاده از رانرهای میزبان‌شده‌ی GitHub: «هر فعالیت دیگری که به تولید، تست،
  استقرار یا انتشار پروژه‌ی نرم‌افزاری مرتبط با همان مخزن مربوط نباشد».

منبع: https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features

**ترجمه‌ی عملی:** اگر کرون هر ۵ دقیقه در Actions اجرا شود و مشتری بابت خروجی آن پول
بدهد، این یک سرویس تجاری است که روی Actions اجرا می‌شود — دقیقاً همان چیزی که ممنوع است.
اضافه بر آن، GitHub ورک‌فلوهای زمان‌بندی‌شده را در مخازن عمومی پس از ۶۰ روز
بی‌فعالیتی غیرفعال می‌کند؛ یعنی حتی اگر ممنوع هم نبود، یک کسب‌وکار را روی آن نمی‌شود
بنا کرد.

**پس چه شد:** Actions فقط تست می‌کند، می‌سازد، مستقر می‌کند و منتشر می‌کند — چهار کاری
که خودِ استثناها نام برده‌اند. اجرای واقعی روی Cloudflare Workers است.

## ۲. GitHub Pages: میزبان کسب‌وکار نیست

شرایط Pages می‌گوید Pages «برای استفاده به‌عنوان میزبان وب رایگان جهت اجرای کسب‌وکار
آنلاین، فروشگاه اینترنتی یا هر سایتی که عمدتاً معاملات تجاری را تسهیل می‌کند یا
نرم‌افزار تجاری به‌عنوان سرویس ارائه می‌دهد، در نظر گرفته نشده و مجاز نیست».
(فقط کمک‌های مالی و کراودفاندینگ مجاز شمرده شده.)

**پس چه شد:** سایت روی **Cloudflare Pages** است، نه GitHub Pages. اسم‌ها شبیه‌اند،
محدودیت‌ها نه.

## ۳. کرون در Workers

Cloudflare Workers در پلن رایگان cron trigger دارد. محدودیت واقعی، **زمان CPU** است
(نه زمان انتظار شبکه). این پروژه در هر اجرا چند درخواست HTTP و چند نوشتن در D1 انجام
می‌دهد که در سقف رایگان جا می‌شود. اگر روزی سنگین شد:

- شمارش صرافی‌ها را به دو کرون جدا تقسیم کن؛ یا
- پلن ۵ دلاری Workers را بگیر (باز هم ارزان‌تر از هر VPS).

در `docs/RUNBOOK.md` آمده چه علامتی نشان می‌دهد به این سقف خورده‌ای.

## ۴. اسکرپینگ و منابع داده

- فقط **صفحه‌های عمومی اعلان** خوانده می‌شود؛ هیچ ورود، هیچ داده‌ی شخصی، هیچ
  دورزدن محدودیتی.
- فرکانس پایین است (هر ۵ دقیقه، ۸ منبع) و User-Agent معرفی می‌شود.
- متن کامل مقاله ذخیره **نمی‌شود**؛ فقط تیتر، زمان، نماد و لینک منبع. تیتر یک «واقعیت»
  است؛ بازنشر کامل متن، حق تکثیر ناشر را نقض می‌کند.
- اگر صرافی‌ای `robots.txt` یا شرایطش اسکرپینگ اعلان‌ها را منع کند، آن منبع باید
  حذف شود. مسیر امن‌تر: API رسمی یا RSS اگر وجود دارد — ساختار `sources.js` برای همین
  طراحی شده که اندپوینت عوض شود بدون تغییر بقیه‌ی کد.

## ۵. پول و تحریم: ریسکی که باید صریح درباره‌اش حرف زد

واقعیت‌ها:

- تقریباً همه‌ی درگاه‌های کارت و اکثر سرویس‌های Merchant-of-Record (Stripe، Lemon
  Squeezy، Polar، Paddle، Gumroad) برای کاربران ایران سرویس نمی‌دهند. این انتخاب
  «سلیقه» نبود؛ USDT تنها مسیر عملی با سرمایه‌ی صفر بود.
- تحریم‌های آمریکا (OFAC) معاملات اشخاص آمریکایی با ایران را محدود می‌کند. فروش
  نرم‌افزار و داده به مشتریان خارج از آمریکا، از منظر شما، معمولاً در محدوده‌ی این
  ممنوعیت‌ها نیست — ولی **interpretation حقوقی لازم است** و من متخصص آن نیستم.
- ریسک عملی‌تر: پلتفرم‌ها (Cloudflare، Telegram، GitHub) ممکن است بنا به سیاست خودشان
  حساب‌هایی با نشانه‌های ایران را محدود کنند. دروغ گفتن درباره‌ی موقعیت مکانی معمولاً
  به بستن حساب و از دست رفتن موجودی منتهی می‌شود؛ مسیر پایدار، شفاف بودن و آماده بودن
  برای مهاجرت است.
- راه‌حل بلندمدت متعارف: ثبت یک شرکت در حوزه‌ی قضایی بی‌طرف (گرجستان، ارمنستان، امارات)
  و انتقال درگاه‌ها به آن. این کار هزینه و زمان دارد و برای مرحله‌ی «اولین ۱۰ مشتری»
  لازم نیست.

**توصیه‌های عملی برای امروز:**
1. فقط داده و نرم‌افزار بفروش، نه خدمات مالی و نه مشاوره سرمایه‌گذاری.
2. سابقه‌ی پرداخت‌ها را نگه دار (فایل `invoices` همین کار را می‌کند).
3. تراکنش مشکوک را نپذیر؛ USDT برگشت‌ناپذیر است.
4. کیف پول کسب‌وکار را از کیف پول شخصی جدا کن.
5. هیچ‌وقت ادعا نکن در کشوری هستی که نیستی.

## ۶. محتوای مالی

محصول «اطلاعات» می‌فروشد، نه توصیه. در سایت و کانال:

- جمله‌ی «این توصیه سرمایه‌گذاری نیست» باید در فوتر و در پست‌ها باشد (در قالب سایت
  هست).
- هیچ‌جا «سود تضمینی» یا «سیگنال خرید» نوشته نشود.
- امتیاز سیگنال باید توضیح‌پذیر باشد (همین است که `reasons` در کد اجباری است).

## ۷. داده‌ی شخصی

تنها داده‌ی شخصی که ذخیره می‌شود، در بدترین حالت `telegram_chat` است (برای تحویل
دسترسی). نه ایمیل، نه نام، نه آدرس کیف پول مشتری. اگر بعداً اضافه کردی، سیاست
حذف/نگهداری هم لازم می‌شود.
